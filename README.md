## About

I build complete systems rather than isolated components — mobile clients, REST APIs, real-time services, and the desktop tools that sit alongside them.

My work starts from concrete local problems. **El-Mawqaf** came from watching commuters wait at microbus stations with no way to know whether a vehicle was coming; it became a Flutter app, an Express API with Socket.IO, and role-scoped operator dashboards. The **Cashier System** came from small restaurants priced out of licensed POS software and underserved by English-only interfaces; it ships as an offline-first Windows installer with a runtime Arabic/English switch.

What I care about in practice: software that survives unreliable connectivity, interfaces that treat Arabic as a first-class layout rather than a translation pass, and authorisation enforced in one place instead of scattered across controllers.

## Architecture Experience

Things I have designed and shipped, rather than read about:

| Pattern | Where | What it involved |
|---|---|---|
| **Three-tier distributed system** | El-Mawqaf | Flutter client + Express API + MongoDB, with two web dashboards sharing one backend |
| **Role-based access control** | El-Mawqaf | Three-level hierarchy (super admin → governorate admin → operator) enforced through composable middleware, not per-controller checks |
| **Multi-tenant data scoping** | El-Mawqaf | Operators confined to an assigned station, governorate admins to a governorate — applied at the query layer with a Mongoose plugin |
| **Real-time event fan-out** | El-Mawqaf | Socket.IO broadcasting state changes so clients update without polling |
| **Clean architecture** | El-Mawqaf mobile | `data` / `domain` / `presentation` split with repository interfaces and Cubit state |
| **Layered desktop application** | Cashier System | Presentation / logic / persistence separation where the data layer never imports the UI toolkit, making export and invoicing independently testable |
| **Offline-first design** | Both | Local caching, connectivity awareness, and graceful degradation rather than error screens |
| **Declarative security rules** | BMW Egypt | Firestore default-deny with per-user scoping and explicit privilege-escalation blocking |
| **Internationalisation (RTL)** | Both | Arabic-first layouts with runtime language switching, not a translation afterthought |
